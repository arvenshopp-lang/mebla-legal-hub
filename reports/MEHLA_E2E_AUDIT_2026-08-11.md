# تقرير دراسة واختبار منصة مِهلة

التاريخ: 11 أغسطس 2026  
النطاق: GitHub وLovable والنسخة المنشورة وSupabase المتصل واختبارات واجهة حية للمالك/مدير المنصة.  
القاعدة: لم تُحفظ أو تُنسخ بيانات الدخول، ولم تُنفذ عمليات إنشاء أو حذف أو إرسال أو دفع أو تغيير صلاحيات في الإنتاج.

## القرار التنفيذي

المنصة متقدمة وظيفياً وتغطي المنتج القانوني SaaS بصورة واسعة، لكنها ليست جاهزة لإعلان إغلاق E2E كامل لكل الأدوار في وضعها الحالي. توجد أربعة موانع رئيسية:

1. مستودع GitHub عام ويحتوي ملف `.env` متتبعاً وملف إعادة إنتاج تجريبي يتضمن بيانات شخصية/فوترة صريحة. لم تُقرأ قيم `.env` أثناء التدقيق.
2. مشروع Supabase المتصل بالموصل ليس قاعدة الإنتاج التي تخدم `mehlalex.com`؛ لذلك لا يمكن اعتماد تدقيق RLS أو جميع الصلاحيات على الإنتاج من الموصل الحالي.
3. مزامنة Hostinger Agentic Mail تفشل دورياً برسالة `Stream was cancelled`، مع 12 مهمة بريد فاشلة ومسارات إعادة محاولة غير منضبطة للحجب النهائي.
4. التحقق بخطوتين اختياري حتى لحساب مالك المنصة، والحارس الحساس يوثّق أن AAL2 إلزامي بينما التنفيذ لا يمنع العملية عند غيابه.

## النتائج مرتبة حسب الأولوية

### حرجة/عالية

#### 1. تعرّض محتمل لبيانات في مستودع عام

- المستودع مرئي للعامة.
- `.env` ملف متتبع في Git وحجمه غير صفري. لم تُقرأ قيمه في هذا التدقيق.
- `tmp-repro/pdf.ts` متتبع ويحتوي بيانات شخصية وفوترة صريحة بدل بيانات اصطناعية.

الإجراء: اجعل المستودع خاصاً بعد موافقة المالك، احصر مفاتيح `.env` ودوّر أي سر غير عام، أزل `.env` من التتبع وأضف مثالاً بلا قيم، واحذف ملف إعادة الإنتاج أو حوّل بياناته إلى قيم اصطناعية. لا تنفذ Force Push أو إعادة كتابة تاريخ Lovable تلقائياً؛ عالج التاريخ كحادث منفصل ومنسق.

#### 2. Supabase المتصل ليس إنتاج مِهلة

- الموصل يعرض مشروع `Mehlalex` بحالة صحية، لكن العدّ الفعلي فيه: 0 مكاتب، 0 اشتراكات، 0 تذاكر، 0 قضايا، 0 أعضاء.
- الإنتاج الحي يعرض 35 مكتباً و40 اشتراكاً و93 تذكرة مفتوحة وبيانات قضايا فعلية.
- المشروع الآخر المتاح في Supabase يخص نظام POS/مطاعم، وليس مِهلة.

الأثر: لا يمكن اعتماد نتائج Advisors أو RLS أو العزل أو صلاحيات الأدوار على قاعدة الإنتاج الحالية. يلزم ربط المشروع الصحيح عبر OAuth/الموصل الرسمي، دون إرسال Service Role في المحادثة.

#### 3. فشل مزامنة البريد المتكرر

- جولات المزامنة تفشل كل خمس دقائق تقريباً برسالة `Stream was cancelled`.
- السبب الجذري في `src/lib/email/agentic/mcp-client.server.ts`: `readLimited` ينتظر نهاية تدفق SSE بالكامل قبل تحليل جواب JSON-RPC. التدفق طويل العمر قد لا ينتهي، فتقوم الاستضافة بإلغائه.

الإصلاح: محلل SSE تزايدي يتوقف فور وصول `result/error` المطابق لمعرّف الطلب، يدعم الحزم المجزأة، يلغي القارئ بعد الحصول على الجواب بصورة مقصودة، ويميّز timeout/cancel عن فشل المصادقة.

#### 4. MFA غير مفروض على العمليات الحساسة

- حساب مالك المنصة الحالي بلا MFA.
- `sensitive-guard.server.ts` يذكر أن AAL2 إلزامي، لكن السطر التنفيذي يصرح بأن MFA اختياري ويعيد مستوى الجلسة فقط.

الإصلاح: فرض Step-up MFA تدريجياً على مالك المنصة والصلاحيات الحساسة، مع وضع `observe → grace → enforce` ومسار استرداد موثق حتى لا يُقفل حساب المالك فجأة.

### متوسطة

#### 5. بيانات QA ملوثة للإنتاج

- مركز الدعم يحتوي عشرات تذاكر `QA-LOAD` و`QA-PROBE` مفتوحة، إضافة إلى حسابات منصة QA كثيرة.
- سكربتات الحمل تنشئ بيانات في مسار الإنتاج ولا تضمن التنظيف عند توقف الجولة قبل نهايتها.

الإصلاح: بيئة staging مستقلة، حارس يمنع E2E المدمر على production افتراضياً، `try/finally` للتنظيف، وخطة تنظيف قديمة تُعرض أولاً ولا تُنفذ دون موافقة.

#### 6. إعادة محاولة بريد محجوب نهائياً

- قائمة الوظائف تعرض زر إعادة المحاولة لرسائل سببها `recipient_suppressed` رغم أن النص يقول إنها لن تُعاد.
- دالة `retryEmailJob` تعيد الحالة إلى `queued` وتزيد `max_attempts` دون فحص رمز الفشل النهائي.

الإصلاح: تصنيف الأخطاء إلى retryable/terminal، منع الخادم والواجهة من إعادة terminal jobs، وإجراء bulk-close/acknowledge مدقق بدلاً من زيادة المحاولات.

#### 7. مسارات إدارة قديمة تعرض Not Found خام

- `/mehla-admin/finance`
- `/mehla-admin/health`
- `/mehla-admin/audit`

لا تتحول إلى `/revenue` و`/monitoring` و`/logs`، وتعرض `Not Found` خاماً لا صفحة 404 العربية.

#### 8. تعيين مسؤول باسم متكرر

نماذج القضية والمهلة والمهمة تعرض عضوين بالاسم نفسه دون البريد أو الدور، ما يسمح باختيار المستخدم الخطأ. يلزم عرض `الاسم — الدور — البريد المقنّع` مع هوية `user_id` ثابتة.

#### 9. سياسة CSP واسعة في الإنتاج

- `frame-ancestors` يسمح لأي `*.lovable.app` و`*.lovable.dev` بتضمين المنصة.
- `script-src` يسمح بـ`unsafe-eval` و`unsafe-inline`.

الإصلاح: سياسة تعتمد البيئة؛ `mehlalex.com` يسمح بـ`self` فقط للتضمين، والمعاينة تسمح بأصول Lovable الضرورية بدقة. أزل `unsafe-eval` من الإنتاج، وانتقل إلى nonce/hash للـinline متى سمح إطار العمل.

#### 10. سلامة رفع/حذف المستندات

الرفع يتم إلى Storage ثم إدخال صف قاعدة البيانات؛ فشل الإدخال يترك ملفاً يتيماً. الحذف يزيل Storage قبل تأكيد حذف الصف؛ فشل القاعدة يترك صفاً لملف مفقود. يلزم Server Function مع تعويض/rollback وسجل تدقيق.

#### 11. حالة التشغيل الحالية

- 93 تذكرة دعم مفتوحة، 92 منها غير مسندة.
- 12 رسالة بريد فاشلة.
- 14 مهمة فاشلة إجمالاً: 12 بريد و2 معالجة مستندات/OCR.
- Webhook دفع واحد فاشل/بانتظار المعالجة.
- Moyasar غير مربوط، وWhatsApp تنقصه هوية جهاز وقالب رسمي.

هذه ليست كلها أخطاء كود؛ بعضها جاهزية تشغيل/مزود. يجب عرض `غير مهيأ` منفصلاً عن `غير صحي` وعدم إعلان القناة جاهزة قبل اختبار اتصال إنتاجي.

### جودة وتوثيق

- `README.md` ما زال يصف مرحلة Landing Page فقط، وهو لا يمثل المنتج الحالي.
- وثائق المالك والإغلاق تتعارض مع الحالة الحية وتعلن إغلاقاً كاملاً رغم الأعطال التشغيلية والتلوث التجريبي.
- `scripts/e2e/plan3_actions.e2e.ts` يحتوي شرطاً ثابتاً `false &&` يفشل ESLint.
- `tmp-repro/pdf.ts` يسبب خطأي `no-explicit-any` ويجب ألا يكون ملفاً إنتاجياً متتبعاً.
- 52 تحذيراً من Fast Refresh/React Hooks.
- Build يطلق تحذيرات واسعة عن `createServerFn().inputValidator()` المتقادم؛ يلزم ترحيل مخطط على دفعات مع اختبارات انحدار.
- أغلب الحقول المطلوبة في نماذج المكتب تعتمد Zod بصرياً، لكن لا تضع `required` أو `aria-required` برمجياً؛ الدعم فقط يضعها.

## ما لم يُختبر ويجب ألا يُسمى PASS

- إنشاء/تعديل/حذف سجلات إنتاجية.
- إرسال بريد أو SMS أو WhatsApp أو إشعار حقيقي.
- دعوات أعضاء أو تغيير أدوار أو انتحال مستخدم.
- دفع Moyasar أو Webhook إنتاجي.
- رفع/تنزيل/طباعة/مشاركة مستند حي في هذه الجولة.
- عزل RLS الحالي على قاعدة الإنتاج.
- جميع أدوار المكتب الخمسة وجميع قوالب منصة الإدارة بحسابات حية منفصلة.
- Safari/WebKit الفعلي واختبارات تحميل/تزامن حالية.

## بوابة القبول بعد الإصلاح

لا تعتبر الجولة مغلقة إلا بعد:

1. ربط Supabase الإنتاج الصحيح ونجاح Advisors الأمني دون High/Critical غير مبرر.
2. Build وTypeScript وESLint = صفر أخطاء.
3. Security/RBAC/fonts = PASS، وتحديث تدقيق القوالب إلى 20 دون رقم صلب قابل للتقادم.
4. E2E على staging لخمس أدوار المكتب، وعينة كاملة من أدوار المنصة، وعزل مستأجرين A/B ومستخدم خارجي.
5. نجاح بريد MCP لثلاث دورات متتالية دون `Stream was cancelled`.
6. لا وظائف terminal قابلة لإعادة المحاولة، ولا QA tickets مفتوحة في الإنتاج.
7. MFA مفروض للمالك والعمليات الحساسة بعد انتهاء فترة السماح.
8. لا نشر ولا تنظيف جماعي ولا تدوير مفاتيح دون موافقة المالك.
