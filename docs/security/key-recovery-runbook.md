# دليل إجراءات استعادة وتدوير مفاتيح التشفير (MEHLA Key Recovery & Rotation Runbook)

> **تصنيف الوثيقة:** سري — للاستخدام الأمني والتقني المعتمد  
> **الإصدار:** 1.0  
> **المنصة:** مِهلة | MEHLA Legal SaaS  
> **النطاق:** مفاتيح تشفير الحقول الحساسة (PII)، بيانات الهوية، السجلات التجارية، وبيانات الاعتماد.

---

## 1. ملكية المفاتيح والحوكمة (Key Governance & Dual Control)

1. **الجهة المسؤولة:** فريق أمن المعلومات والمنصة (Principal Security Engineer + System Custodian).
2. **مبدأ الرقابة الثنائية (Dual Control):** لا يجوز لأي شخص بمفرده توليد أو كشف أو حذف أو تدوير مفاتيح التشفير الرئيسية في بيئة الإنتاج دون مصادقة وحضور مسؤولين معتمدين.
3. **فصل البيئات:** مفاتيح بيئة التطوير والاختبار معزولة ومستقلة تماماً عن مفاتيح بيئة الإنتاج الحية.

---

## 2. هيكلية التشفير والمسميات (Key Hierarchy & Naming Convention)

تعتمد المنصة نمط **Envelope Encryption** واشتقاق المفاتيح الفرعية لكل مستأجر:

| المفتاح | متغير البيئة / الخزنة | الغرض | خوارزمية التشفير |
|---|---|---|---|
| **Master Key (Vn)** | `MEHLA_MASTER_KEY_V<n>` | المفتاح الرئيسي لاشتقاق مفاتيح المكاتب | HKDF-SHA256 (256-bit) -> AES-256-GCM |
| **Blind Index Key (Vn)** | `MEHLA_BLIND_INDEX_KEY_V<n>` | المفتاح الرئيسي لفهارس البحث الحتمية | HKDF-SHA256 -> HMAC-SHA256 |
| **Active Version Pointer**| `MEHLA_ACTIVE_PII_KEY_VERSION` | تحديد الإصدار النشط لعمليات الكتابة الجديدة | مؤشر رقمي (Integer e.g. `1`, `2`) |

*ملاحظة أمنية:* لكل مكتب (`organization_id`) ولكل حقل (`field`) يُشتق مفتاح فرعي فريد لحظياً في الذاكرة عبر HKDF مع حزمة بيانات مصادقة إضافية (AAD).

---

## 3. سيناريو تدوير المفاتيح المجدول (Graceful Key Rotation)

عند انتهاء دورة حياة المفتاح المعتمدة (مثلاً سنوياً) أو لرفع الجاهزية الأمنية:

```text
[ 1. توليد V2 ] ──► [ 2. تسجيل V2 في الخزنة ] ──► [ 3. تحويل الكتابة إلى V2 ] ──► [ 4. إعادة تشفير تدريجية ] ──► [ 5. أرشفة V1 ]
```

### خطوات التنفيذ:
1. **توليد مادة المفاتيح الجديدة (V2):**
   ```bash
   # توليد 32 بايت (256-bit) عشوائية مشفرة بصيغة Base64
   openssl rand -base64 32
   ```
2. **إضافة المفاتيح في إعدادات البيئة (Secret Manager):**
   - إضافة `MEHLA_MASTER_KEY_V2`
   - إضافة `MEHLA_BLIND_INDEX_KEY_V2`
3. **تفعيل الإصدار الجديد للكتابة:**
   - تعيين `MEHLA_ACTIVE_PII_KEY_VERSION=2`.
   - يبدأ النظام فوراً بكتابة السجلات الجديدة بإصدار V2 بينما تظل السجلات القديمة قابلة للقراءة التلقائية عبر V1.
4. **إعادة التشفير التدريجية (Gradual Re-encryption):**
   - تشغيل مهمة إعادة التشفير الدفعية عبر الخادم (`reencryptValue`).
   - التحقق من انخفاض عدد الصفوف المرتبطة بـ V1 إلى صفر في جدول `encryption_key_registry`.
5. **إيقاف المفتاح القديم (Retirement):**
   - بعد التأكد من عدم وجود أي سجل مشفر بـ V1، يُعلّم المفتاح كـ `retired` في السجل وتُحفظ نسخته المشفرة في الخزنة الباردة.

---

## 4. سيناريو الطوارئ: الاشتباه باختراق مفتاح (Emergency Compromise Rotation)

في حال تسرب أو الاشتباه بتسرب أي مفتاح رئيسي:
1. **إعلان حالة طوارئ أمنية:** إبلاغ مسؤول الحماية وضابط الامتثال.
2. **توليد إصدار جديد فوراً (Vn+1):** وضعه في الخزنة وتوجيه `MEHLA_ACTIVE_PII_KEY_VERSION` إليه.
3. **تشغيل إعادة تشفير فورية (Emergency Sweep):** إعادة تشفير كافة جداول `clients` و `case_parties` بدون تأخير.
4. **عزل وإلغاء المفتاح المسرب:** منع قراءة أي بيانات جديدة به وتدقيق سجلات الوصول `pii_access_logs` لمعرفة الحقول التي تم كشفها خلال فترة التسرب.

---

## 5. النسخ الاحتياطي واستعادة البيانات (Backup Restore Dependency)

- **الاعتمادية الحرجة:** قواعد البيانات المنسوخة احتياطياً تحوي نصوصاً مشفرة بإصدار المفتاح الذي كُتبت به.
- **شرط الاستعادة:** لاستعادة نسخة احتياطية تاريخية (Point-in-Time Restore)، يجب الاحتفاظ بنسخ تاريخية محمية ومؤرشفة من المفاتيح (`MEHLA_MASTER_KEY_V1`, `V2`, ...) في خزنة الاستعادة المخصصة للكوارث (Disaster Recovery Vault).
- **منع الحذف النهائي للمفاتيح:** يُحظر حذف أي مادة مفتاح رئيسي قديمة طالما توجد نسخ احتياطية صالحة قد تحتاج للاسترجاع.

---

## 6. التحقق والاختبار (Verification Procedure)

قبل اعتماد نجاح أي عملية تدوير أو استعادة:
1. **فحص Canary Decryption:** محاولة فك تشفير عينة سجلات من كل مكتب والتأكد من تطابق الـ AAD.
2. **فحص Blind Index Consistency:** التحقق من قدرة النظام على البحث بالرقم القومي / السجل التجاري واسترجاع النتائج بدقة.
3. **فحص Fail-Closed:** التأكد من أن محاولة فك التشفير بمفتاح غير صحيح أو AAD مزور تُرجع `null` فوراً دون كشف أي بيانات.

---

## 7. خارطة التوطين في السعودية (Saudi KMS / HSM Target Architecture)

عند انتقال البنية التحتية إلى استضافة سحابية سعودية مخصصة:
- سيتم ربط اشتقاق المفاتيح مباشرة بـ **KMS سحابي محلي (Saudi Cloud KMS)** أو جهاز أمان عتادي **(Cloud HSM)** معتمد من الهيئة الوطنية للأمن السيبراني (NCA).
- تصبح المفاتيح الرئيسية غير قابلة للاستخراج (Non-Exportable) ويتم التشفير والفك داخل بيئة الـ HSM المعزولة.
