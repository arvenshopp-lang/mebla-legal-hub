| `mehla-notifications-dispatch` | `* * * * *` | `/api/public/hooks/notifications-dispatch` |

## Required per-environment configuration

- `ops.runtime_secrets.cron_secret` is generated by the earlier cron-auth migration. Never copy it between environments or place it in Git.
- `ops.runtime_secrets.cron_base_url` must contain that environment's HTTPS origin only, with no path, query, or fragment. The migration does not invent or hardcode this value.

The migration validates both values before it changes any schedules. If either is absent or invalid, the transaction fails closed and preserves existing jobs. Configure the environment origin through a controlled database administration step before applying the migration:

```sql
INSERT INTO ops.runtime_secrets (name, secret)
VALUES ('cron_base_url', 'https://<environment-host>')
ON CONFLICT (name) DO UPDATE
SET secret = EXCLUDED.secret, updated_at = now();
```

Provisioning is idempotent and can be reconciled again after configuration:

```sql
SELECT ops.reconcile_mehla_cron_jobs();
```

Verify topology without exposing secrets:

```sql
SELECT jobname, schedule, active
FROM cron.job
WHERE jobname LIKE 'mehla-%'
ORDER BY jobname;
```
