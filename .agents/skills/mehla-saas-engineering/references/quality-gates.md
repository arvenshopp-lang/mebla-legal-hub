# بوابات التطوير والاختبار

## قبل التعديل

- اقرأ التوثيق والـAGENTS وحالة Git.
- حدّد العقدة المتأثرة ومصدر الحقيقة والمخاطر الأمنية والمالية.
- أنشئ حالة إعادة إنتاج أو اختباراً يفشل عند إصلاح عطل مهم.

## الاختبارات المطلوبة حسب التغيير

| التغيير | الحد الأدنى للإثبات |
|---|---|
| مكوّن واجهة | اختبار سلوك + فحص RTL والجوال + لقطة بصرية عند الحاجة |
| API أو Edge Function | نجاح وفشل ومدخلات غير صالحة وصلاحية وسجل تدقيق |
| RLS أو صلاحيات | مستخدم مصرح + غير مصرح + مكتبان مختلفان + تصعيد دور |
| مستندات | رفع صالح ومرفوض وعرض وتنزيل ورابط منتهي وعلامة مائية |
| فوترة | حدود المبالغ والتكرار والإقفال وSandbox وعدم استخدام Float |
| بريد أو دعم | حفظ قاعدة البيانات حتى عند فشل المزود + Queue/Retry/Dead letter |
| Webhook | توقيع صحيح وخاطئ وتكرار وReplay ومعرف تتبع منقح |
| Migration | تطبيق على قاعدة اختبار + توافق خلفي + خطة Rollback أو Forward fix |

## بوابة الإصدار

1. الاختبارات المستهدفة ناجحة.
2. Regression للوظائف المرتبطة ناجح.
3. Type Check وESLint وProduction Build ناجحة.
4. الرحلة الأساسية مختبرة E2E فعلياً عند تأثرها.
5. النجاح والفشل والصلاحيات والجوال موثقة بصدق.
6. لا توجد مشكلات Critical أو High مفتوحة.

استخدم المصطلحات بدقة: `مبني` لا يعني `مختبر`، و`مختبر آلياً` لا يعني `مختبر حياً`.
