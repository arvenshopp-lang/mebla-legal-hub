# أمان وبيانات مِهلة

## ثوابت الحماية

- استخدم Supabase Auth وRLS والتحقق الخادمي لكل قراءة وكتابة حساسة.
- طبّق `tenant/office_id` على كل مسار بيانات، واختبر منع الوصول المتبادل بين مكتبين.
- إخفاء زر أو Route في العميل ليس صلاحية.
- امنع تصعيد الدور؛ لا يمنح المستخدم صلاحية أعلى مما يملك.
- اجعل Owner أو `super_admin` الاستثناء الوحيد عندما تنص المعمارية الحالية على ذلك.
- سجّل النجاح والفشل والمحاولات المرفوضة والعمليات الإدارية الحساسة في Audit Log.
- لا تكشف Secrets أو Tokens أو كلمات المرور أو Stack Traces في الواجهة أو السجلات أو Git.

## المستندات

- استخدم Storage خاص وروابط موقعة قصيرة الصلاحية.
- تحقق من الحجم والامتداد وMIME وMagic Bytes قبل القبول.
- لا تسمح بعرض HTML أو JSON كمستند.
- طبّق سياسة العلامة المائية على العرض والتنزيل والطباعة والمشاركة.
- لا تكشف روابط متابعة العميل ملاحظات داخلية أو ملفات خاصة.

## التكاملات والمالية

- تحقق من توقيع Webhooks وطبّق Idempotency ومنع Provider Reference المكرر.
- افصل إنشاء تذكرة الدعم عن نجاح إرسال البريد؛ قاعدة البيانات هي مصدر الحقيقة والبريد إشعار غير متزامن.
- لا تستخدم `Float` للأموال، ولا تسمح بدفع أكبر من الفاتورة أو استرداد أكبر من المدفوع.
- لا تعدّل فاتورة أو فترة مالية مقفلة.
- استخدم أقل صلاحية وبيانات QA معزولة في الاختبارات.
