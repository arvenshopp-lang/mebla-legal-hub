# التحقق من ربط مستودع arvenshopp-lang/mebla-legal-hub (Git Sync)

## ما تم فحصه فعلياً الآن
- موصل GitHub API مربوط بالمشروع والرمز صالح، لكن طلب قراءة المستودع `arvenshopp-lang/mebla-legal-hub` أعاد **404**، وقائمة المستودعات المتاحة للرمز أعادت **[] فارغة** — أي أن هذا الرمز لا يملك وصولاً لأي مستودع (Fine-grained token دون منح المستودع).
- هذا الموصل منفصل تماماً عن **مزامنة كود المشروع (Git Sync)**؛ لا يمكن استنتاج حالة Git Sync منه، ولا يمكنني تفعيل Git Sync أو قراءة حالته من جهتي.

## الخطوات المطلوبة منك (تفعيل/تأكيد Git Sync)
1. في محرر المشروع: قائمة **(+)** في مربع المحادثة ← **GitHub** ← **Connect project**.
   - على الجوال: وضع الدردشة ← **(+)** ← GitHub.
2. صرّح لتطبيق Lovable على GitHub، واختر حساب **arvenshopp-lang**.
3. إن ظهر المستودع `mebla-legal-hub` في القائمة فاختره؛ وإن لم يظهر فامنح تطبيق Lovable وصولاً لهذا المستودع من GitHub (Settings ← Applications ← Lovable ← Repository access) ثم أعد المحاولة.
4. أخبرني بمجرد ظهور حالة "Connected" في القائمة.

## ما سأنفذه بعد ذلك (تحقق فعلي لا شكلي)
1. إثبات وجود آخر commit فعلي من Lovable في المستودع، وتطابق الفرع الافتراضي.
2. مقارنة عدد/أسماء ملفات جذر المشروع مع محتوى المستودع للتأكد أن المزامنة كاملة وليست جزئية.
3. تقرير صريح: ما تم إثباته فعلياً، وما تعذر إثباته وسببه.

## ملاحظة صحّية مهمة
- إصلاح صلاحيات رمز موصل GitHub API (حتى يرى المستودعات) عمل منفصل. إن أردته لاحقاً أعرض بطاقة إعادة ربط برمز يملك صلاحية قراءة المستودعات — لا حاجة له لعمل Git Sync.
- المستودع خاص: تأكد ألا يحتوي أي أسرار؛ أسرار المنصة تبقى في إعدادات الأسرار ولا تُدفع إلى المستودع.
