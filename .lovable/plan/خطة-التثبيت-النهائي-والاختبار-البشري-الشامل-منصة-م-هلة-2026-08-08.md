## G. خطة الاختبار البشري في المعاينة

جلسة المعاينة حالياً غير مسجّلة الدخول، لذا تبدأ كل زاوية بعد تسجيلك اليدوي — بلا جلسات مصطنعة.

الأسلوب لكل شاشة: فتح المسار، الضغط على كل زر ظاهر، تعبئة الحقول بنص عربي طويل، إنشاء ثم تعديل ثم حذف حيث يُسمح، تحديث الصفحة، رجوع/تقدّم، رابط عميق مباشر، إدخال خاطئ لرؤية رسالة الخطأ، حالة فراغ، حالة تحميل، مراقبة الطرفية والشبكة وسجل الأعطال بعد كل خطوة.

- الزاوية أ — مالك المنصة: كل مسارات /mehla-admin الموجودة فعلاً بما فيها التبويبات.
- الزاوية ب — مكتب محاماة: مكتب QA حقيقي، من لوحة التحكم إلى الفريق والدعوات وحدود الباقة.
- الزاوية ج — عميل خارجي: رمز متابعة، رابط رفع، رابط آمن منتهٍ، رمز خاطئ، إعادة استخدام الرمز، وتأكيد عدم ظهور الملاحظات الداخلية أو بيانات مكتب آخر.

## H. مصفوفة الأدوار

لكل دور من الثمانية (super_admin، الدعم، المالية، المبيعات، الموارد البشرية، الأمن، المراجع، قراءة فقط) يُسجَّل: ما يظهر في القائمة، ما يُفتح، ما يمنعه الواجهة، ما يمنعه الخادم، قراءة مسموحة، كتابة مسموحة، قراءة ممنوعة، كتابة ممنوعة، رابط مباشر، استدعاء إجراء مباشر، محاولة تبديل organization_id، محاولة تلاعب بالدور/الصلاحية، وتسجيل الرفض في التدقيق. تُضاف مصفوفة أدوار المكتب (مالك/مدير/محامٍ/موظف/محاسب/قراءة) ومصفوفة العميل الخارجي.

## I. مصفوفة الجوال

عروض 320 / 375 / 390 / 430 / 440 / 768 / 1024 / 1440 مع فحص بصري بلقطات: المنطقة الآمنة، لوحة المفاتيح، النوافذ والأدراج والقوائم، الجداول والمرشّحات والرسوم، النص العربي الطويل، الأشرطة الثابتة، القائمة الجانبية، الأزرار ≥ 44px، انعدام التمرير الأفقي، صحة RTL. أي عطل يُعالج في المكوّن المشترك (AdminShell، أدوات القوائم، النوافذ، المرشّحات) ثم Regression على كل الصفحات التي تستخدمه.

## J. مصفوفة إغلاق الأمن

RLS، عزل المستأجر، RBAC خادمي، استخدام مفتاح الخدمة، SECURITY DEFINER ومنح الدوال، سياسات التخزين، الروابط الموقّعة وانتهاؤها، تشفير البيانات الحساسة والفهارس العمياء، عدم قابلية تعديل سجل التدقيق، حدود المعدل، XSS، حقن CSV، رفع الملفات، اجتياز المسارات، عدم تسريب الأسرار والسجلات، ترويسات البريد، رموز الدعوة، OTP، توقيع الويب هوك، منع التكرار. تُراجع التبعيات لتحديد الثغرات المؤثرة فعلاً فقط مع خطة ترقية آمنة — بلا ترقيات عشوائية.

## L. تنظيف بيانات QA

بادئة موحّدة QA-E2E-20260808- لكل ما يُنشأ. بعد الاختبار: حذف الأدوار والحسابات المؤقتة من موظفي المنصة (بما فيها الصفَّين القديمين)، حذف المكاتب والعملاء والقضايا والتذاكر والمستندات القابلة للحذف، إغلاق الجلسات، حذف الملفات المؤقتة، وعدم لمس سجلات التدقيق أو أي بيانات حقيقية.

## M. بوابة الإصدار

تُكتب عبارة «MEHLA CORE PLATFORM = RELEASE READY» فقط عند تحقق كل ما يلي بدليل: صفر عطل Critical/High؛ عزل المستأجر مثبت بمحاولة اختراق فعلية؛ RBAC خادمي مثبت للأدوار الثمانية بتوكنات حقيقية؛ كل رحلة أساسية تعمل من البداية للنهاية؛ رحلة الدعم والبريد كاملة بإرسال واستقبال حقيقي؛ لا تمرير أفقي على مستوى الصفحة في أي مقاس؛ كل زر أساسي يعمل أو معطّل بسبب واضح؛ الأرقام المالية صحيحة ومطابقة للقاعدة؛ تثبيت نظيف + Type Check + ESLint + بناء إنتاجي + security:all + مراجعة التبعيات، بلا أخطاء في الطرفية أو الشبكة. المزودون غير المربوطين يُصنّفون READY FOR PROVIDER CONNECTION ولا يمنعون جاهزية النواة.
