# اختبارات E2E لاستوديو التصميم (Playwright) — معاينة، مسودة، وقيود الأدوار

الهدف: تحويل الاختبار اليدوي الذي نُفّذ هذا الدور إلى سكربت قابل للتشغيل المتكرر، يُثبت فعلياً حفظ المسودة، فتحها بعد إعادة التحميل، عمل جسر المعاينة، وقيود الأدوار على الحفظ والنشر والاسترجاع.

## الملفات المضافة
- `scripts/e2e/design_studio_e2e.py` — السكربت الرئيسي (Playwright، نمط `rbac_nav_e2e.py`: عربي، PASS/FAIL مرقّم، لقطات في `/tmp/browser/design`).
- `scripts/e2e/design-studio-fixture.ts` — تهيئة/تنظيف حسابي اختبار عبر Service Role: `qa.design.owner@mehlaqa.test` بدور `super_admin`، و`qa.design.designer@mehlaqa.test` بدور `staff` وصلاحيات `design.read` + `design.draft.write` + `design.preview` + `design.history.read` فقط. يكتب الجلستين في `/tmp/browser/design-sessions.json` ويحذف الحسابين مع `--cleanup`.
- سكربت في `package.json`: `"design:e2e": "python3 scripts/e2e/design_studio_e2e.py"`.

## مصفوفة الاختبار (كل بند PASS/FAIL صريح)

مالك المنصة (super_admin):
1. فتح `/mehla-admin/design` وتحميل الاستوديو (وجود أزرار الحفظ والنشر والسجل).
2. حفظ مسودة صالحة (`تعديل توكن + CSS مخصص بمُعرِّف فريد للجولة`) → توست نجاح، ثم إعادة تحميل الصفحة والتأكد أن المسودة معروضة كما حُفظت (فتح Draft).
3. القفل التفاؤلي: حفظ متزامن مرتين من نفس الصفحة → أحدهما يُرفض برسالة عربية بلا فقد بيانات.
4. رفض CSS محظور: `@import`, `url()` خارجي، إخفاء عنصر تسجيل الخروج، `z-index` مفرط → رفض مع رقم سطر ورسالة عربية، ولا تُحفظ المسودة.
5. المعاينة: تحميل الإطار، إثبات وجود عنصر الأنماط المحقون وقيمة CSS المسودة داخل الإطار، وثبات الوضع بعد تحويل داخلي (`/` → `/onboarding`) — الحماية من انكسار الجسر.
6. المعاينة على المقاسات الثلاثة (1280/834/390) دون تمرير أفقي داخل الإطار.
7. سجل الإصدارات يُعرض ويحتوي رقم الإصدار النشط.

مصمم المنصة (staff بصلاحيات المسودة فقط):
8. يرى الصفحة و«حفظ مسودة فقط» مفعّلاً، ويحفظ مسودة بنجاح.
9. «حفظ ونشر الآن» و«استرجاع آخر تصميم منشور» **معطّلان** مع سبب مقروء.
10. تجاوز الواجهة: إلغاء `disabled` من DOM ثم النقر → الخادم يرفض والحالة في قاعدة البيانات لا تتغير (تُقاس بـ `cache_version` قبل/بعد).
11. مستخدم بلا صلاحيات تصميم: لا يرى رابط «مظهر المنصة» ويُمنع من المسار برسالة الصلاحية.

النشر والاسترجاع (يعملان على التصميم الحقيقي، ولذلك مضبوطان):
12. النشر بمسودة الجولة → إصدار جديد + ارتفاع `cache_version` + `rollback_available = true`.
13. الاسترجاع (مع تأكيد نافذة `confirm`) → العودة إلى الإصدار السابق، ارتفاع `cache_version`، و`rollback_used_at` غير فارغ.
14. **إرجاع الحالة** في نهاية السكربت: التأكد أن الإصدار النشط هو نفسه المسجَّل قبل بدء الجولة، وإلا FAIL صريح.
15. سجل التدقيق `design_audit_logs` يحتوي أحداث: `save`, `publish`, `rollback`، ومحاولة مرفوضة.

## تفاصيل تقنية
- الجلسات حقيقية عبر `/auth/v1/token`؛ لا توكن مزيّف: الهدف إثبات الحماية الخادمية لا العميل فقط.
- التحقق من قاعدة البيانات داخل السكربت عبر REST بمفتاح Service Role من البيئة، للقراءة فقط في التحقق (لا كتابة مباشرة على جداول التصميم).
- لا تُطبع التوكنات ولا كلمات المرور ولا مفاتيح الخدمة.
- النقر على أزرار تستخدم `window.confirm` يتطلب معالج `dialog` — سبب فشل ظاهري في الاختبار اليدوي، وسيُعالج داخل السكربت.
- الوسم الفريد لكل جولة (`QA-DESIGN-<timestamp>`) داخل CSS المسودة لتمييز أثر الاختبار في السجل.
- شرط الإغلاق: `FAIL = 0` مع تأكيد إرجاع التصميم المنشور لحالته السابقة.

## خارج النطاق
لا تعديل على منطق الاستوديو أو الصلاحيات أو RLS أو أي Migration — إضافة اختبارات فقط.
