# إصلاح حفظ القوالب + مستند PDF احترافي لعرض السعر

## 1) سبب عطل «تعذّر حفظ القالب» (مؤكَّد بفحص قاعدة البيانات)

في جدول `sales_document_templates` العمودان `created_by` و`updated_by` من نوع `uuid`،
بينما كود الحفظ يكتب فيهما **البريد الإلكتروني** للموظف (`staff.email`). لذلك كل عملية
حفظ ترفضها قاعدة البيانات، وجدول القوالب فارغ تماماً (صفر صفوف) — أي أن الحفظ لم ينجح ولا مرة.

مشكلتان مصاحبتان ظهرتا في نفس الفحص:
- قاعدة البيانات تشترط مدة صلاحية بين 1 و365 يوماً، والتحقق في الواجهة يسمح بـ 0 → رفض صامت آخر.
- دالة `fail()` تُلغي تفاصيل خطأ قاعدة البيانات، فتصل للمستخدم رسالة عامة بلا سبب.

الإصلاح:
- كتابة `staff.user_id` في `created_by/updated_by` (مع مراجعة بقية عمليات الكتابة في وحدة العروض للتأكد من عدم تكرار نفس الخلط).
- توحيد حد مدة الصلاحية على 1–365 في مخطط التحقق والواجهة.
- تمرير سبب الخطأ الحقيقي إلى سجل الخادم ورسالة عربية دقيقة للمستخدم دون كشف تفاصيل تقنية.

## 2) إعدادات هوية المستندات (قابلة للتعديل من لوحة الإدارة)

قسم جديد «هوية المستندات» داخل إعدادات المركز المالي/العروض، يُخزَّن في `platform_settings`
ويشمل: اسم الجهة، الاسم التجاري بالإنجليزية، العنوان، الجوال، البريد، الموقع،
السجل التجاري، الرقم الضريبي، بيانات التحويل البنكي، اسم وصفة الموقّع، وتذييل مخصص.
كل هذه الحقول تظهر مباشرة في الـ PDF بلا أي تعديل على الكود لاحقاً.

## 3) تصميم PDF احترافي لعرض السعر بهوية مِهلة

يُبنى على محرك PDF العربي الموحّد الحالي (نفس الخط والتشكيل العربي وضبط الأرقام)،
بإضافة عناصر اختيارية لا تغيّر شكل الفواتير القائمة:

```text
┌──────────────────────────────────────────────┐
│ الشعار + مِهلة | MEHLA        عرض سعر        │
│ العنوان · الجوال · البريد     MEH-QT-2026-…  │
├──────────────────────────────────────────────┤
│ موجّه إلى:                 بيانات العرض:     │
│ اسم الشركة/العميل          تاريخ الإصدار     │
│ عناية: جهة الاتصال          صالح حتى         │
│ الجوال · البريد            العملة            │
├──────────────────────────────────────────────┤
│ جدول البنود (البند/الكمية/السعر/الخصم/الإجمالي)│
│ الإجماليات + الضريبة + الإجمالي بارز         │
├──────────────────────────────────────────────┤
│ المقدمة · الشروط والأحكام                     │
│ مساحة توقيع الطرفين (اسم/صفة/تاريخ)          │
│ تذييل: بيانات التواصل + السجل + رقم الصفحة   │
└──────────────────────────────────────────────┘
```

- بطاقة «موجّه إلى» بصياغة سعودية مهنية (شركة/مؤسسة/السيد) مع اسم جهة الاتصال والجوال.
- تنويه واضح أن المستند عرض سعر وليس فاتورة ضريبية.
- شعار المنصة في الرأس مع تدرّج ذهبي رقيق وخط أخضر عميق، وفواصل هادئة بلا زخرفة.
- ترقيم صفحات وتكرار رأس مختصر عند تعدد الصفحات.

## 4) إصدار عرض سعر لأي جهة بدون إدخالها في CRM

حالياً بيانات العميل تأتي من شركة/جهة اتصال في CRM فقط. سنضيف حقولاً اختيارية على
`sales_documents` (اسم الجهة، جهة الاتصال، الجوال، البريد) تُستخدم في المستند والـ PDF
عند عدم وجود سجل CRM، مع إبقاء ربط CRM كما هو حين يُختار.

## 5) الحفظ والإرسال

- زر «تنزيل PDF» موجود ويبقى كما هو (بعد تحسين التصميم).
- إضافة «مشاركة عبر واتساب»: يفتح `wa.me` برقم جهة الاتصال ونص عربي جاهز يحتوي رقم العرض
  والإجمالي والصلاحية، مع تنزيل الملف ليُرفق في المحادثة (لا نرسل ملفات لواتساب دون تكامل رسمي).

## التفاصيل التقنية

| العمل | الملفات |
| --- | --- |
| إصلاح الحفظ | `src/lib/sales-docs.server.ts`, `src/lib/sales-docs.schemas.ts`, `src/components/admin/sales/templates-panel.tsx` |
| إعدادات الهوية | `src/lib/billing/billing.server.ts` (أو مفتاح إعدادات مستقل) + واجهة الإعدادات في `src/routes/mehla-admin` |
| محرك PDF | `src/lib/billing/pdf/engine.server.ts` (حقول اختيارية: تواصل، مستلم، توقيع)، `src/lib/sales-docs.pdf.server.ts` |
| حقول المستلم | Migration على `sales_documents` + النموذج والتفاصيل |
| واتساب | `src/routes/mehla-admin/sales/$id.tsx` |

Migration واحدة توافقية (أعمدة اختيارية فقط، بلا تغيير أسماء أو صلاحيات قائمة).

## الاختبار قبل الإعلان

- حفظ قالب جديد وتعديله وحذفه فعلياً والتحقق من الصفوف في قاعدة البيانات.
- إصدار عرض سعر لجهة خارجية بدون CRM، توليد PDF، وفحص كل صفحة بصرياً (RTL، الأرقام، عدم قطع النص).
- تجربة الجوال (390px) لأزرار التنزيل والمشاركة، وTypecheck وESLint نظيفان.
