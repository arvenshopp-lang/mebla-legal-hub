# خطة الفحص الشامل قبل الانطلاق — Master Pre-Launch QA Audit

تدقيق عملي صارم (خادم + قاعدة بيانات + واجهة) لكل مسارات مِهلة، ثم **تقرير مصنّف حسب الخطورة**. **لا إصلاح ولا تعديل برمجي في هذه المرحلة**.

## تصحيحان قبل البدء (حسب الوضع الفعلي للكود)

- **الفوترة الضريبية (ZATCA 15%) غير موجودة في المنصة**: ميزة الأتعاب والفواتير حُذفت بالكامل بطلبك سابقاً (المسار والجداول والمكونات)، لذا لا يمكن اختبار إصدار فاتورة ضريبية أو سند قبض. سيُختبر بدلاً منها **فوترة اشتراكات مِهلة نفسها** في لوحة الإدارة + العقود، ويُسجَّل بند ZATCA كـ **NOT APPLICABLE** بسبب صريح.
- **الخط الرسمي هو IBM Plex Sans Arabic** (مستضاف محلياً) لا Readex Pro، وسيُفحص على هذا الأساس.

## ما تأكّد فعلياً من القراءة قبل الاختبار (مرشّحات أعطال تُثبت أو تُنفى)

- الباقات الفعلية أربع: `free` 0، `basic` 199، `professional` 499، `enterprise` 1499 — كلها مفعّلة. الاشتراكات: 43 نشط، 8 ملغى.
- البوابة الخادمية `assertEntitlement` منطقها سليم لكنها مستخدمة في **4 مواضع فقط** (طلبات المستندات، الصفحة العامة للمكتب، ذكاء المستندات، دالة فحص الاشتراك). لا أثر لها في التوقيع الإلكتروني أو الصوت أو API → **مرشّح P1**.
- `FeatureGate` الواجهي مستخدم في مسار واحد فقط (`/search`).
- الحدود العددية (`max_cases`, `max_clients`, `max_users`, `max_documents`, `storage_gb`) لا تظهر إلا في صفحات العرض ومنطق التسعير؛ الاستثناء المفعّل الوحيد هو `consume_ocr_pages` → **مرشّح P1 (تجاوز صامت)**.

## المرحلة 1 — بوابات الميزات والحصص

- 4 مكاتب QA معزولة بالبادئة `QA-PLAN-20260818-`، لكل منها اشتراك فعلي على باقة، ثم فحص الميزات السبع = **28 خلية**.
- **Fail-Closed Assertion**: كل ميزة غير مشمولة تُجرّب مرتين — من الواجهة، ثم باستدعاء دالة الخادم مباشرة بتوكن مستخدم تلك الباقة — والمطلوب رفض خادمي برسالة عربية صريحة لا 500 ولا نجاح.
- **Quota Stress**: تجاوز `max_cases`، تجاوز `storage_gb` برفع مستند، استهلاك `consume_ocr_pages` بعد نفاد الرصيد، وتجاوز `max_users` بدعوة عضو — وإثبات: منع أم تجاوز صامت.
- مطابقة الأرقام المعروضة في `/subscription` مع الواقع، وسلوك حالات الاشتراك: نشط/تجربة/منتهٍ/موقوف/ملغى.

## المرحلة 2 — الصلاحيات والعزل

- الأدوار الفعلية في القاعدة: `owner`, `admin`, `lawyer`, `legal_assistant`, `viewer` + بوابة العميل الخارجي (رمز 10 خانات). سيُفحص «المحاسب» كطلب صريح ويُسجَّل إن لم يكن دوراً قائماً.
- لكل دور: عمليات مسموحة تُنفَّذ فعلاً، وممنوعة تُرفض من الخادم/RLS — كل رفض يُثبت مرتين (واجهة + استدعاء خادمي مباشر).
- **Cross-Tenant Intrusion**: مستخدم المكتب A يحاول قراءة/تحميل قضية ومستند وعقد وتذكرة وبيانات أطراف قضية من المكتب B بتزوير المعرّف في الطلب المباشر — المطلوب حظر تام.
- محاولة تصعيد صلاحية (منح دور أعلى من دور الفاعل) + التأكد من تسجيل كل محاولة مرفوضة في سجل التدقيق.

## المرحلة 3 — المسارات الوظيفية الحية

- **العقود والتوقيع**: إنشاء عقد → رابط `/sign/$token` → توقيع باللمس → بصمة SHA-256 → PDF رسمي بصفحة تنفيذية واحدة بلا تداخل تذييل.
- **الدفع**: بوابة الدفع غير مربوطة → كل مسار دفع يُسجَّل **BLOCKED**، مع اختبار أن الواجهة تُظهر تنبيهاً عربياً واضحاً لا خطأ برمجي، واختبار مسار التفعيل اليدوي وزر «اشترك» في `/pricing`.
- **خزينة المستندات والوسم**: رفع PDF → علامة مائية خادمية بهوية المكتب والمحامي، سلامة تشكيل العربية والأقواس، رقم النسخة، وصف `print_audit_logs`، ومنع الطباعة لدور غير مصرَّح.
- **التخزين الهجين**: منع الرفع غير المصرح وإلزام تفويض Microsoft OAuth عند اختيار OneDrive.
- بقية الرحلات: عميل، قضية، جلسة، مهلة، مهمة، دعوة فريق، تذكرة دعم وSLA وسرية الملاحظة الداخلية، CRM، العروض والمقترحات، البريد، الموارد البشرية، التسويق، بوابة العميل، الصفحة العامة للمكتب.
- **المزوّدون المربوطون**: OTP والواتساب — اختبار اتصال/حالة حقيقي بلا إرسال جماعي، وتوثيق ما نجح فعلاً.

## المرحلة 4 — الواجهة والتجاوب

- مسح مصادق لكل المسارات على 320 / 390 / 768 / 1024 / 1440: صفر تمرير أفقي، صفر أخطاء Console، صفر طلبات 4xx/5xx غير متوقعة، أهداف لمس ≥ 44px، سلامة RTL وخط IBM Plex Sans Arabic.
- تحقق من الحالات الأربع في كل جدول وصفحة: Loading / Empty / Error / Retry، وأن كل زر ظاهر يعمل أو معطّل بسبب مفهوم، وأن رسائل الخطأ عربية دون كشف تفاصيل داخلية.
- بوابات آلية: Type Check + ESLint + Production Build + `security:all` + Security Linter + سكربتات الاختبار القائمة في `package.json`.

## المخرَج: `docs/qa/full-platform-audit-2026-08-18.md`

1. جدول **مصفوفة الباقات × الميزات (4×7)** بحالة كل خلية ومصدر التحقق (خادم / RLS / واجهة فقط).
2. سجل الأعطال مصنّفاً: **P0 حرجة** (أمان، تسريب، انهيار خادمي) — **P1 عالية** (ميزة بلا فحص خادمي، تجاوز حصة صامت) — **P2 متوسطة** (تعطل تدفق، رسالة غامضة) — **P3 منخفضة** (بصري/تنسيق)، ولكل عطل: خطوات الإنتاج، السبب الجذري المُثبت، الملف/الدالة، الأثر، الإصلاح المقترح.
3. جدول **PASS** مع الدليل (المسار / الحمولة / الاستجابة / صف قاعدة البيانات / لقطة).
4. جدول **BLOCKED / NOT TESTED / NOT APPLICABLE** بأسبابه (الدفع، ZATCA، أي إرسال إنتاجي).
5. **حكم صريح Go / No-Go** مع التوصيات الإجرائية المرتّبة.

## تفاصيل تقنية

- التشغيل محلياً على `http://localhost:8080` عبر Playwright (نقر حقيقي) + استعلامات قراءة على القاعدة؛ لا يُعتمد على Toast النجاح كدليل.
- بيانات QA معزولة ببادئة `QA-PLAN-20260818-`، وحاجز أمان في كل سكربت كتابة يمنع لمس بيانات حقيقية، وتنظيف كامل بعد الانتهاء مع الإبقاء على سجلات التدقيق.
- تنفيذ على دفعات مع ملف نتائج تراكمي حتى لا تُعاد الدفعات المنتهية.
- بلا أي Migration وبلا تعديل كود في هذه المرحلة؛ كل عطل يُسجَّل ويُقترح إصلاحه في خطة تالية بعد اعتماد التقرير.
