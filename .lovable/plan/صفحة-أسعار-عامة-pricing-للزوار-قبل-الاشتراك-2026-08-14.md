# صفحة أسعار عامة `/pricing` للزوار قبل الاشتراك

## المشكلة المؤكدة
- لا يوجد أي مسار عام للأسعار في `src/routes/` (يوجد about / how-it-works / faq / security / contact فقط).
- الصفحة الرئيسية `src/routes/index.tsx` لا تحتوي قسم أسعار (الأقسام الحالية: capabilities / how / workflow / security).
- رأس الموقع العام في `src/components/marketing/public-shell.tsx` لا يحتوي رابط «الأسعار».
- الباقات موجودة فعلياً في `platform_plans` بأسعار حقيقية: الأساسية 199، الاحترافية 499، المؤسسات 1499 ريال شهرياً (والسنوي 1990 / 4990 / 14990)، وكلها `is_public = true`. الباقة المجانية `is_public = false`.

النتيجة: الزائر لا يرى أي معلومة عن التكلفة قبل إنشاء الحساب.

## ما سيتم بناؤه
صفحة `/pricing` عامة (RTL، بهوية مِهلة) تقرأ الباقات المنشورة من قاعدة البيانات مباشرة — بدون أي Migration وبدون لمس الجداول المالية أو الاشتراكات، ما يحافظ على بوابتي RECOVERY GATE و FEATURE_READY.

المحتوى:
1. عنوان الصفحة + مبدّل «شهري / سنوي» يوضح قيمة الخصم السنوي المحسوبة من الأسعار الفعلية (لا نسبة مكتوبة يدوياً).
2. ثلاث بطاقات باقات مرتّبة بـ `sort_order`، تعرض السعر بالريال، الحدود الحقيقية (المستخدمون، القضايا، العملاء، المستندات، التخزين، صفحات القراءة الضوئية) ومستوى الدعم وSLA من نفس الصفوف.
3. المزايا تُعرض من الأعلام الفعلية في الجدول (`pdf_search_enabled`, `client_upload_enabled`, `public_office_page`, `esignature_enabled`, `voice_enabled`, `api_enabled`, `ai_enabled`) مع علامة واضحة «متوفر / غير مشمول»، ووسم «قريباً» للمزايا المعطّلة على مستوى المنصة حتى لا نَعِد بما ليس جاهزاً (قاعدة FEATURE TRUTH).
4. جدول مقارنة كامل على الشاشات الكبيرة، ويتحول إلى بطاقات على الجوال (لا تمرير أفقي للصفحة).
5. زر كل باقة: «ابدأ الآن» يوجّه إلى `/register` عبر `useSurfaceHref` (نطاق app)، مع تمرير `?plan=<code>` كمعلومة توجيه فقط. لا يوجد أي وعد بالدفع أو التفعيل الفوري؛ التفعيل يبقى داخل مساحة العمل كما هو اليوم.
6. باقة المؤسسات تُضيف رابطاً إلى `/contact` لطلب تفاصيل.
7. تنبيه شفاف: الأسعار لا تشمل ضريبة القيمة المضافة إن كان ذلك واقع النظام الحالي (سأصيغه بحياد: «تُطبّق الأنظمة الضريبية السعودية على الفواتير الصادرة»)، وأن الدفع الإلكتروني غير مفعّل حالياً وتُفعّل الباقات عبر فريق مِهلة.
8. أسئلة شائعة قصيرة (٤–٥) خاصة بالباقات، مع رابط لصفحة الأسئلة الشائعة الكاملة.
9. حالات Loading / Empty / Error عربية واضحة مع إعادة محاولة.

## الربط
- إضافة «الأسعار» إلى قائمة `NAV` في `public-shell.tsx` (سطح المكتب والجوال).
- إضافة رابط الأسعار في `site-footer.tsx`.
- إضافة قسم مختصر في الصفحة الرئيسية (٣ بطاقات مبسّطة بالسعر الشهري) يقود إلى `/pricing`، دون تغيير باقي أقسام الصفحة.
- إضافة `/pricing` إلى `sitemap.xml`.

## التفاصيل التقنية
- مسار جديد: `src/routes/pricing.tsx` داخل `PublicShell`، مع `head()` خاص (title/description/og/twitter) وJSON-LD من نوع Product/Offer بأسعار حقيقية.
- القراءة عبر `createServerFn` جديدة في `src/lib/pricing.functions.ts` (غير محمية بمصادقة، آمنة للـ SSR والـ prerender) + منطق في `src/lib/pricing.server.ts` يستخدم عميل النشر العام ويقرأ `platform_plans` بـ `is_active = true and is_public = true` فقط، مع اختيار الأعمدة صراحةً.
- منطق العرض المشترك في `src/lib/pricing.shared.ts`: ترتيب المزايا، تسميات عربية، حساب الخصم السنوي، تنسيق الحدود (يُعاد استخدام `FEATURE_LABELS` و`fmtNumber` الموجودين، دون تعديل `subscription.shared.ts`).
- مكونات العرض في `src/components/marketing/pricing/` (بطاقة باقة، جدول مقارنة، مبدّل الفترة) قابلة لإعادة الاستخدام.
- التحميل عبر `context.queryClient.ensureQueryData` في الـ loader + `useSuspenseQuery` في المكوّن.
- بدون `any`، وبدون بيانات وهمية، واحترام `prefers-reduced-motion` وأهداف لمس 44px وWCAG AA.

## ما لن يتم
- لا Migration ولا تغيير أسعار أو أسماء باقات في قاعدة البيانات.
- لا تنفيذ بوابة دفع ولا تعديل الفواتير أو الويبهوك.
- لا تنفيذ لهيكل الباقات المقترح (فردي/احترافي/أعمال) — يبقى خطة معتمدة مؤجلة.
