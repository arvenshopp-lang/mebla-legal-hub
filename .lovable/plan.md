# ربط GitHub بالمشروع والتحقق من الباك-إند

## الوضع الحالي (تم فحصه فعلياً)
- **الباك-إند (قاعدة البيانات والمصادقة)**: مربوط ويعمل — المشروع نشط وغير موقوف، والمفاتيح موجودة في بيئة المشروع، والجداول والسياسات مستخدمة فعلياً في التطبيق. لا حاجة لأي ربط جديد.
- **GitHub**: يوجد اتصال في مساحة العمل باسم "Ziad's GitHub API" لكنه **غير مرتبط بهذا المشروع**، لذلك لا تتوفر مفاتيحه في بيئة التشغيل الآن.
- الموصلات المرتبطة بالمشروع حالياً: Google Search Console و PostHog فقط.

## المطلوب تنفيذه
1. **ربط موصل GitHub API بالمشروع**
   - عرض بطاقة الربط لاختيار الاتصال "Ziad's GitHub API" وربطه بالمشروع.
   - بعد الربط تصبح مفاتيح الاتصال متاحة كمتغيرات بيئة خادمية فقط، ولا تُستخدم إطلاقاً في كود المتصفح.

2. **التحقق الفعلي من الاتصال**
   - إجراء طلب تحقق حقيقي عبر بوابة الموصلات (قراءة فقط، مثل بيانات الحساب/المستودعات) لإثبات أن الرمز صالح وليس مجرد ربط شكلي.
   - في حال أي خطأ من المزود يُعرض السبب الحقيقي بوضوح (صلاحيات ناقصة / رمز منتهي) مع الخطوة التصحيحية.

3. **تأكيد حالة الباك-إند**
   - فحص صحة قاعدة البيانات والمصادقة وتأكيد عدم وجود تحذيرات تشغيلية، وإبلاغك بالنتيجة.

## ما لن يُنفَّذ في هذه الجولة
- لا تعديل على أي وحدة قائمة، ولا صفحات أو جداول جديدة، ولا أي ميزة GitHub داخل المنصة (مثل عرض المستودعات أو المشكلات) — هذه تحتاج طلباً منفصلاً بعد تحديد المكان والصلاحيات المطلوبة.
- **مزامنة الكود مع GitHub (Git Sync)** شيء مختلف عن هذا الموصل ولا يمكن تفعيلها من جهتي؛ تُفعّل من قائمة (+) في المحادثة ← GitHub ← Connect project. سأشرح الخطوات إن رغبت.

## تفاصيل تقنية
- الربط يتم عبر أداة الموصلات الرسمية (`standard_connectors--connect` بمعرّف `github`)، والاتصال يعمل في وضع البوابة (gateway) لذا تُوجَّه الطلبات إلى `connector-gateway.lovable.dev/github` من الكود الخادمي فقط.
- لا يُخزَّن أي مفتاح في المستودع أو في حزمة المتصفح، والتحقق يتم بطلب قراءة غير مؤثر.
