## 2) جدول الفجوات والقرارات

| المجال | النقص / الخطر | القرار المقترح |
|---|---|---|
| صلاحيات دقيقة | لا يمكن اليوم منح مصمم وصولاً: `requireOwner` يرفض كل من ليس `super_admin` حتى لو ملك `design.manage` | تفكيك إلى `design.draft.write` `design.preview` `design.history.read` `design.publish` `design.rollback` مع إبقاء `design.manage` كصلاحية أعلى عبر `PERMISSION_IMPLIES` |
| دور المصمم | لا قالب دور Platform Designer | إضافة قالب في `src/lib/rbac/role-templates.ts` — نفس النظام الحالي، بلا جدول جديد |
| حرس الدوال | حرس واحد موحّد لكل الدوال | حرس لكل عملية: القراءة/المسودة/المعاينة/السجل بصلاحيتها، والنشر والرجوع لـ super_admin أو `design.publish`/`design.rollback` صراحة |
| مناعة الإصدارات | `design_versions` بلا trigger؛ `deny_update()`/`deny_hard_delete()` موجودتان في القاعدة لكن غير مرتبطتين | Migration واحدة تربطهما بـ `design_versions` و`design_audit_logs` بلا تغيير أعمدة |
| بيانات المعاينة | المعاينة تفتح المسارات الحقيقية بجلسة المستخدم → مصمم بلا صلاحيات مكتب يرى صفحات فارغة، وSuper Admin يرى بيانات حقيقية | وضع معاينة بمكتب عرض (Demo Org) مفروض من الخادم عند `__design=1` — قراءة فقط (انظر القرار 1) |
| فحص CSS | فحص نصي بلا AST، ولا رقم سطر في الرفض | تحقق AST خادمي بـ `postcss` (JS نقي متوافق مع Worker) داخل `css-guard.ts` مع إبقاء كل القواعد الحالية، وإرجاع `line`/`column` |
| الأصول | لا مدير أصول للخطوط/الصور | لا توسّع الآن: `url()` مقصور على مسار داخلي أو `data:image` — يُوثّق كقرار معتمد |
| الفروق | لا Diff بين المسودة والمنشور | لوح Diff للتوكنات وCSS يُحسب في الواجهة من بيانات `getDesignStudio` الحالية بلا API جديد |
| فحوصات ما قبل النشر | لا فحص تباين ولا كشف overflow | فحص تباين للتوكنات + كشف `scrollWidth > clientWidth` داخل إطار المعاينة كتحذيرات ما قبل النشر |
| فاحص العناصر | استخراج المحددات موجود، لا فاحص بالنقر | Inspector بالنقر داخل الإطار عبر نفس جسر الرسائل: selector مستقر + الخصائص المحسوبة + التوكنات المستخدمة |
| `data-ui` مستقرة | موجودة جزئياً (`data-slot`, `data-app-*`) | إضافة سمات `data-ui` محدودة للأسطح الناقصة فقط (شريط الأدوات، الجدول، النافذة، التنبيه) بلا محددات مكررة |

## 3) القرار المعماري
نُبقي المعمار الحالي: مسودة لكل `page_key` + إصدارات Immutable + حزمة CSS واحدة من `/api/public/theme.css` + عزل `[data-page]`. كل الجديد هو **طبقات صلاحيات وتحقق وواجهة** فوق هذا الأساس. لا جدول جديد ولا Route جديد إلا مسار حالات واجهة واحد اختياري (Empty/Error/Modal) إن لم تكفِ الصفحات الحقيقية.

## 4) التعديلات المقترحة
- `src/lib/admin-permissions.ts`: 5 صلاحيات تصميم + سلسلة implies.
- `src/lib/rbac/role-templates.ts`: قالب دور «مصمم المنصة».
- `src/lib/design/theme.functions.ts`: حرس لكل دالة بصلاحيتها بدل `requireOwner` الموحّد.
- `src/lib/design/css-guard.ts`: تحقق AST + أرقام أسطر برسائل عربية.
- `src/lib/design/preview-bridge.ts` + `design-preview.tsx`: رسائل Inspector وكشف overflow.
- `src/routes/mehla-admin/design.tsx`: تبويب المحددات، Diff، فاحص العناصر، فحوصات ما قبل النشر، تعطيل أزرار النشر/الرجوع حسب الصلاحية (والمنع الحقيقي على الخادم).
- Migration واحدة: ربط `deny_update`/`deny_hard_delete` على `design_versions` و`design_audit_logs`؛ الجداول تبقى بلا GRANT للعميل.
- طبقة معاينة بيانات العرض: حرس خادمي في قارئات الصفحات المعنية عند `__design=1`.

## 6) الأمان والعزل
- كل تحقق داخل `.handler()` على الخادم قبل أي عملية؛ إخفاء الأزرار تحسين تجربة فقط.
- الجداول تبقى بلا GRANT للعميل → لا وصول مباشر من المتصفح.
- CSS يُفحص مرتين: عند الحفظ وعند النشر؛ لا يُخزَّن CSS غير مفحوص كإصدار منشور.
- ممنوع صراحة: `@import`، `url()` خارجي، `@font-face` بمصدر خارجي، iframe، إخفاء عناصر أمان/تنبيهات، طبقات تغطية كامل الشاشة، حجم أكبر من 100KB.
- المسودة تُحقن في إطار اللوحة فقط عبر رسائل مقيّدة بالأصل والنافذة الأم → لا تظهر لأي مستخدم إنتاج.

## 7) الإصدارات والنشر والرجوع
يبقى المسار الحالي: مسودة بقفل تفاؤلي → فحص → Snapshot Immutable برقم إصدار وناشر وتاريخ وملخص → `cache_version++` → ثبات CSS بعد التحديث وتسجيل الخروج/الدخول. الرجوع ينشئ إصداراً جديداً ولا يحذف التاريخ. تُضاف فحوصات ما قبل النشر (تباين، overflow، الصفحات المتأثرة، تحذير عند لمس شاشة الدخول أو الأزرار الخطرة).

## 8) خطة التنفيذ المرتبة
1. **RBAC وحرس الدوال** — الصلاحيات الخمس + قالب الدور + حرس لكل دالة. خطر: منع Super Admin بالخطأ → اختبار مباشر. الرجوع: إعادة `requireOwner`.
2. **مناعة قاعدة البيانات** — ربط triggers على الإصدارات والتدقيق. خطر: منع تحديث مشروع لحالة النشر → التأكد أن النشر يكتب صفوفاً جديدة فقط.
3. **تحقق AST + أرقام أسطر** — بلا تغيير القواعد. خطر: رفض CSS كان مقبولاً → اختبار CSS المنشور الحالي قبل/بعد.
4. **معاينة بيانات العرض** — عزل خادمي لوضع `__design=1` فقط. خطر: تغيير سلوك الصفحات العادية → الحرس مشروط بالوسيط والصلاحية.
5. **Inspector + Diff + فحوصات ما قبل النشر** — واجهة فقط.
6. **سمات `data-ui`** للأسطح الناقصة + كتالوج محددات موثوق.
7. **اختبار حي** حسب المصفوفة ثم الإغلاق.

## 9) Test Matrix (اختبار حي في المتصفح، لا Type Check فقط)
- مصمم: يعدّل Token، يحفظ، يعاين على صفحة حقيقية → ينجح.
- مصمم: Publish/Rollback معطّل في الواجهة، ومن طلب API مباشر يُرفض برسالة عربية.
- مستخدم عادي: لا يرى الرابط ولا الصفحة، ودوال التصميم ترفضه.
- Super Admin: ينشر، ثبات CSS بعد Refresh وخروج/دخول، ثم يسترجع إصداراً.
- CSS محظور (`@import`، `url()` خارجي، إخفاء تسجيل الخروج) → رفض بسبب ورقم سطر.
- المعاينة لا تُظهر بيانات عملاء أو قضايا حقيقية للمصمم.
- Desktop/Tablet/iPhone على: Login، Dashboard، Clients، Cases، Documents، Settings — بلا overflow أفقي.
- سجل التدقيق يسجّل: حفظ، نشر، رجوع، استعادة، ومحاولة مرفوضة.
