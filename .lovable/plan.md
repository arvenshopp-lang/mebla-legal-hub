# إكمال خطة الإغلاق — إصلاح Harness ثم دليل RBAC خادمي ثم المسح المصادق

الهدف: إكمال Phase B/C/D من نفس النقطة، بلا إعادة أي عمل مغلق، وبلا أي ميزة جديدة أو ربط مزوّد خارجي.

## الوضع المؤكد الآن (بقراءة فعلية)

- `scripts/e2e/rbac_server_e2e.ts` يبني معرّف دالة الخادم بنفسه عبر `fnId()` (base64 لمسار `?tss-serverfn-split`) ويرسل حمولة `seroval`. هذا تخمين لبنية داخلية، ولهذا فشل بـ 500 حتى لمالك المنصة — أي عطل هارنس لا عطل تطبيق.
- بيئة الـ sandbox حالياً `LOVABLE_BROWSER_AUTH_STATUS=signed_out` ولا يوجد `/tmp/browser/auth/state.json` محفوظ، لذا أول خطوة عملية هي إعادة إنشاء جلسة حقيقية بتسجيل دخول فعلي.
- `package.json` لا يحتوي سكربت لتشغيل اختبار الخادم؛ سيُضاف `rbac:server:e2e` فقط.

## 1. إصلاح الـ Harness (بلا أي تغيير في منطق التطبيق)

- استخراج معرّفات دوال الخادم من مصدر الحقيقة بدل تخمينها: تشغيل بناء Vite للـ SSR/الرواتر واستخراج خرائط `_serverFn` الفعلية، أو الأبسط والأكثر متانة — استدعاء الدوال من داخل المتصفح عبر Playwright بـ `useServerFn` نفسه غير ممكن من سكربت خارجي، لذا البديل المعتمد: استخراج المعرّف من طلب شبكة حقيقي.
  - يفتح الهارنس صفحة الإدارة المعنية بجلسة حقيقية، يعترض طلبات `POST /_serverFn/*`، ويبني خريطة `اسم الدالة → المعرّف الحقيقي` مرة واحدة ويخزّنها في `/tmp/browser/rbac/fnmap.json`.
  - بعدها تُستدعى الدوال بالمعرّف الحقيقي وبنفس الترميز الذي رصده الاعتراض (نفس الـ headers والـ body shape المرصودة)، فلا يبقى أي تخمين.
- شرط قبول الإصلاح: كل دالة مسموحة لمالك المنصة تُرجع 2xx. أي 500 لمالك المنصة = الهارنس ما زال معطلاً ولا يُحتسب نتيجة أمنية.

## 2. أدوار وجلسات حقيقية

- حسابات QA بالبادئة `QA-E2E-20260808-` بأدوار منصة فعلية: مالك المنصة، دعم، مالية، تشغيل، قراءة فقط، موظف موقوف، مستخدم بلا صفة موظف.
- تسجيل دخول فعلي لكل حساب للحصول على توكن حقيقي (لا انتحال ولا اعتراض شبكي).
- لكل دور: 3 دوال مسموحة + 3 ممنوعة (مالية / RBAC / أمان) + محاولة قراءة مباشرة لجدولين حساسين عبر Data API لإثبات سحب المنح.
- المعيار: المسموح 2xx، الممنوع مرفوض برسالة عربية من `requireStaff` لا بخطأ 500، والمحاولة المرفوضة مسجّلة في `admin_audit_logs`.
- تنظيف كامل لحسابات QA بعد التشغيل.

## 3. المسح المصادق (47 مسار × 5 مقاسات) على دفعات

- 320 / 390 / 768 / 1024 / 1440 لكل مسار، بجلسة المالك المحفوظة.
- دفعات 8–10 مسارات لكل تشغيل لتجنّب مهلة التنفيذ، مع ملف نتائج تراكمي `/tmp/browser/sweep/results.json` حتى لا تُعاد الدفعات المنتهية.
- لكل مسار: تمرير أفقي على مستوى الصفحة = 0، أخطاء Console = 0، طلبات 4xx/5xx غير متوقعة = 0، عناصر لمس ≥ 44px في الشرائح الأساسية، سلامة RTL.
- أي مشكلة: سبب جذري → إصلاح → Regression على المكوّن المشترك المتأثر → متابعة المسح.

## 4. إكمال Phase B (مراجعة UI/UX/CSS)

- فحص الاتساق: استخدام Design Tokens فقط (لا ألوان مشفّرة)، توحيد حالات Loading/Empty/Error/Retry، توحيد الـ Toasts والعناوين، حالات التركيز للوحة المفاتيح.
- الجداول الكبيرة على الجوال: بطاقات أو تمرير داخلي منضبط.

## 5. إكمال Phase C/D

- C: اختبار وظيفي حي للرحلات المصادقة (عميل، قضية، جلسة، مهلة، مهمة، مستند، دعوة فريق، تذكرة دعم) مع اختبار الفشل والصلاحيات لا النجاح فقط.
- D: إعادة `security:check` و`security:db` و`linter` بعد كل إصلاح، وتصفير أي تنبيه جديد.

## التقرير النهائي

جداول منفصلة بوضوح: **PASS فعلي** (مع دليل: مسار/دور/لقطة) — **غير مختبر** (مع السبب) — **متبقٍ بسبب مزوّد خارجي** (الدفع، WhatsApp WABA، مزوّد OTP — بلا مفاتيح، لن يُلمس الآن).

## تفاصيل تقنية

- التشغيل كله محلياً على `http://localhost:8080` عبر Playwright/Bun؛ لا بيانات إنتاج تُعدَّل، ولا أسرار تُطبع في السجلات أو اللقطات.
- يُضاف `rbac:server:e2e` إلى `package.json` ويخرج بكود 1 عند أي مخالفة ليصلح للـ CI.
