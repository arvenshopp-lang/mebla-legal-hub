# رفع مستوى فحص المستندات الخبيثة — محرك فحص عميق داخلي

الهدف: أي مستند يرفعه المشترك (من داخل المنصة) أو العميل (عبر رابط مؤقت) يخضع لفحص محتوى عميق داخل مِهلة، بلا إخراج أي بايتات خارج المنصة، ويُعرض للمستخدمين بنسخة مطهَّرة بدل الأصل.

القرارات المعتمدة: فحص عميق داخلي فقط (بلا مزوّد خارجي) + تطهير بالتحويل + فحص فوري داخل الطلب.

## الوضع الحالي (تم التحقق منه)
- الفحص الحالي في `src/lib/documents/file-signature.ts` بنيوي فقط: امتداد + بصمة البايتات الأولى + رفض HTML/JSON المتنكر + حد 20MB.
- `runIntakeReleasePipeline` ينقل الحالة (محجوز → قيد الفحص → سليم → مُفرَج) لكن الفحص الحقيقي الوحيد فيه هو الحجم.
- لا يوجد كشف: ماكرو/OLE داخل مستندات Office، JavaScript وأفعال تلقائية داخل PDF، ملفات مدمجة، قنابل ضغط، Polyglot، DDE، روابط خارجية مشبوهة.

## ما سيُبنى

### 1. محرك فحص عميق (داخلي بالكامل)
وحدة جديدة تعمل على البايتات داخل الخادم:
- **PDF**: كشف `/JavaScript` و`/JS` و`/OpenAction` و`/AA` و`/Launch` و`/EmbeddedFile` و`/RichMedia` و`/XFA` و`/GoToR`، والأسماء المموّهة بترميز سداسي، والكائنات المشوّهة، وعمق التضمين.
- **OOXML (docx وما شابه)**: قراءة أرشيف ZIP عبر `DecompressionStream("deflate-raw")` بلا مكتبة خارجية، ورفض `vbaProject.bin` والماكرو وعلاقات `oleObject` و`attachedTemplate` الخارجية وحقول DDE/DDEAUTO والروابط الخارجية غير المطابقة للسياسة.
- **قنابل الضغط**: سقف نسبة تمدد، سقف الحجم غير المضغوط الكلي، سقف عدد المدخلات، سقف عمق التداخل، ورفض Zip-Slip (`../` والمسارات المطلقة).
- **الصور (JPEG/PNG/WEBP/HEIC)**: التحقق من صحة المقاطع/القطع، رفض السكربتات المزروعة في التعليقات، رفض Polyglot (بايتات ملف ثانٍ داخل الملف).
- **قواعد عامة**: رفض تعدد بصمات الملفات داخل الكائن نفسه، رفض المحتوى المشفّر أو المحمي بكلمة مرور (غير قابل للفحص = يُرفض)، وسقف زمني وحجمي للفحص لحماية الموارد.
- كل قاعدة ترجع معرّفاً ثابتاً (مثل `PDF_JS_ACTION`) يُسجَّل في السجل الأمني، بلا كشف تفاصيل داخلية للمستخدم.

### 2. التطهير بالتحويل (Sanitization)
- بعد نجاح الفحص يُنتج المحرك **نسخة معروضة آمنة**: PDF مسطّح خالٍ من الطبقات النشطة (بلا JavaScript ولا Actions ولا مرفقات مدمجة)، وصور مُعاد ترميزها.
- تُخزَّن النسخة الآمنة في مسار مستقل داخل مجلد المكتب نفسه، وتُحسب لها بصمة SHA-256 خاصة.
- الأصل يبقى محفوظاً بحالة محجورة، ولا يُسلَّم إلا للأغراض الداخلية المصرَّح بها (استخراج نص/OCR) عبر بوابة الإفراج الحالية.
- كل مسارات العرض والمشاركة والطباعة والتنزيل ورابط العميل تُسلَّم النسخة الآمنة فقط.

### 3. ربط الفحص بمساري الرفع
- رفع المكتب ورفع العميل عبر الرابط المؤقت يمرّان على المحرك نفسه، بنفس القواعد ونفس الرسائل.
- الفحص فوري داخل الطلب: لا يُقبل المستند ولا يظهر في القائمة قبل صدور القرار. عند الرفض يُحذف الكائن فوراً، وتُسجَّل الحالة `malicious` أو `unscannable` في السجل الأمني غير القابل للتعديل، وتُعرض رسالة عربية واضحة بلا تفاصيل داخلية.
- تشديد الحدود لضمان بقاء الفحص داخل الطلب: سقف حجم للفحص العميق، وما يتجاوزه يُرفض بوصفه غير قابل للفحص بدل تمريره.

### 4. الحوكمة والأدلة
- توسيع سجل الأحداث الأمنية بأسباب الرفض المعرّفة، وربط قرار الإفراج ببصمة النسخة الآمنة.
- تحديث `docs/` بمصفوفة قواعد الفحص لكل صيغة، ومواءمتها مع ضوابط الأمن السيبراني الوطنية (حماية المحتوى الضار، عدم إخراج البيانات، الأثر التدقيقي).
- توسيع حرّاس CI: منع أي مسار عرض أو تنزيل يستهلك الأصل بدل النسخة الآمنة، واختبارات لكل قاعدة فحص بعيّنات صناعية (بلا برمجيات ضارة حقيقية).

## التفاصيل التقنية
- ملفات جديدة: `src/lib/file-security/deep-scan/{index.server.ts,pdf.ts,ooxml.ts,zip.ts,image.ts,rules.ts}` و`src/lib/file-security/sanitize.server.ts`.
- تعديل: `intake.server.ts` (الفحص والتطهير قبل التسجيل)، `security-state.server.ts` (تسجيل قرار الفحص وبصمة النسخة الآمنة)، `release-gate.server.ts` (تسليم النسخة الآمنة للأغراض الخارجية)، ومسارات العرض والمشاركة والطباعة والرابط العام.
- Migration واحدة غير مدمّرة: أعمدة النسخة الآمنة (مسار + بصمة + نتيجة الفحص) على `document_security_state`، مع منح الصلاحيات وتحديث مُشغِّل الانتقالات ليشترط وجود النسخة الآمنة قبل الإفراج الخارجي.
- المستندات الحالية المُفرَج عنها لا تتأثر؛ تُعامل بوضعها الحالي وتُطهَّر عند أول طلب عرض بعد التحديث.
- لا مكتبات خارجية جديدة: ZIP عبر `DecompressionStream`، وPDF عبر `pdf-lib` و`pdfjs-dist` الموجودتين.
