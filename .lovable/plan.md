# فشل رفع حزمة المعاينة (403 AccessDenied) — تقرير فحص Read-only وخطة تعافي

## 1) الحقائق المثبتة

- نص الخطأ كما ورد حرفياً:
```text
dist upload failed: dist upload exit 1: ERROR "cp /tmp/dist.tar.gz s3://previews/0ac4f813-8ba3-4f48-9bc7-432613df3dae/e30deca4/dist.tar.gz": AccessDenied: Access Denied status code: 403, host id:
```
- المرحلة الدقيقة: ليست البناء ولا إنشاء الحزمة. الحزمة `/tmp/dist.tar.gz` أُنشئت فعلاً، والفشل في **خطوة الرفع إلى Preview Storage** (`cp` إلى `s3://previews/...`).
- المعرّفات الظاهرة: Project ID `0ac4f813-8ba3-4f48-9bc7-432613df3dae`، Build/Deployment hash `e30deca4`. لا يوجد `request id` ولا `host id` في نص الخطأ (كليهما فارغ) — أي أن الرفض جاء قبل أن يُصدر التخزين معرّف طلب.
- وقت الحدوث: خلال جلسة اليوم 2026-08-10 بعد آخر تعديلات وحدة التصميم (آخر كتابة ملفات 16:52–16:58 UTC)، والرسالة وردت في المحادثة قبل الساعة 17:19 UTC.
- سجل منصّة Lovable ذكر عطلاً معلناً يمسّ «النشر ومعاينات المشاريع» أثناء نفس النافذة الزمنية، وسجلاً لاحقاً يعلن انتهاء العطل.
- خادم التطوير المحلي داخل بيئة العمل يستجيب `HTTP 200` على `http://localhost:8080/` — أي أن التطبيق نفسه يعمل ويُبنى ويُقدَّم محلياً.
- آخر Migration فعلي: `supabase/migrations/20260810165209_*.sql` ويحتوي أربعة Triggers فقط:
  `design_versions_no_update` / `design_versions_no_delete` / `design_audit_logs_no_update` / `design_audit_logs_no_delete`
  ولا يعدّل أعمدة ولا سياسات RLS ولا GRANT.
- `postcss@^8.5.26` موجود في `package.json`، و`src/lib/design/css-guard.server.ts` يستخدمه لتحليل AST فوق الفحص النصي القائم في `css-guard.ts` دون تخفيف أي قاعدة.

## 2) ما لا يمكن إثباته حالياً

- لا يمكن إثبات أن أي من تغييرات Design Studio تعمل فعلياً في الواجهة: لم يفتح أي متصفح على المعاينة.
- لا يمكن رؤية سجلات بنية الرفع (IAM/Bucket Policy) لأن `s3://previews` تخزين منصّة Lovable ولا يملك المشروع وصولاً إليه.
- لا يوجد `request id` يمكن مطابقته مع أي سجل تخزين، لذلك لا يمكن تأكيد سبب الرفض 403 على مستوى التخزين.
- نجاح Build وType Check وESLint لا يثبت شيئاً عن سلامة الواجهة أو الصلاحيات أو رفض CSS.

## 3) السبب المرجح ومستوى الثقة

| الاحتمال | الدليل | الثقة |
|---|---|---|
| عطل خارجي في Lovable / Preview Storage | الفشل في خطوة `cp` إلى تخزين المنصّة، بلا request id، وتزامنه مع عطل منصّة معلن يمسّ النشر والمعاينات، ثم إعلان انتهائه | **مرتفعة (~85%)** |
| مشكلة صلاحيات تخزين خاصة بالمشروع | 403 قد ينتج أيضاً من مفتاح/سياسة مرتبطة بمسار المشروع؛ لا دليل مباشر ولا وصول للتحقق | منخفضة (~10%) |
| أثر جانبي من تغييرات المشروع الحديثة | لا علاقة سببية ممكنة: الحزمة بُنيت بنجاح والفشل بعد البناء في نقل ملف واحد؛ لا حجم غير طبيعي ولا أصول جديدة | منخفضة جداً (~3%) |
| غير قابل للتأكد الآن | غياب سجلات التخزين ومعرّف الطلب | متبقٍ (~2%) |

## 5) خطة التعافي (بلا تنفيذ)

1. الانتظار حتى تأكيد انتهاء عطل المنصّة على صفحة الحالة، مع اعتبار سجل «انتهى العطل» شرطاً كافياً.
2. عند التأكيد: إعادة محاولة المعاينة **مرة واحدة فقط** عبر إجراء يعيد البناء والرفع (تعديل تافه محفوظ أو زر إعادة المحاولة في الواجهة) — لا تكرار ولا حلقات.
3. إذا نجح الرفع: الانتقال مباشرة إلى خطة الاختبار في القسم 7، ولا تُعتبر أي تغييرات مغلقة قبلها.
4. إذا تكرر `403 AccessDenied`: **التوقف** وفتح تذكرة دعم Lovable مع Project ID و Build hash `e30deca4` والنص الحرفي والتوقيت UTC. لا تعديل كود ولا Migration ولا صلاحيات كردّ فعل على 403.
5. أقل فحص ممكن إن ظهر دليل مباشر على أن المشكلة خاصة بالمشروع (مثل رسالة تذكر حجم الحزمة أو أصلاً محدداً): قياس حجم `dist` وأصول `public/` بحثاً عن ملف كبير أو ثنائي جديد، بلا أي إعادة هيكلة.
6. مراجعة التغييرات الحديثة تكون **بعد** عودة المعاينة وبناءً على نتائج الاختبار الحي فقط، والرجوع عند الحاجة يكون جزئياً ومحدداً: إعادة الحرس الموحّد في `theme.functions.ts`، أو تعطيل مسار فحص AST مع إبقاء الفحص النصي، أو إسقاط Triggers الأربعة — كل واحدة منفصلة وقابلة للتتبع.
7. لا يُقترح إعادة بناء Design Studio ولا تعديل CSS ولا صلاحيات دون عطل مُعاد إنتاجه في المتصفح.

## 6) شروط إعادة المحاولة

- شرط: إعلان انتهاء العطل، أو مرور فترة معقولة مع نجاح عملية نشر/معاينة أخرى في المنصّة.
- عدد المحاولات: **واحدة**.
- معيار النجاح: فتح رابط المعاينة وتحميل الصفحة الرئيسية دون خطأ.
- معيار الفشل: أي 403 آخر ⇒ توقف وتذكرة دعم.

## 8) قرارات مطلوبة منك

- **قرار وحيد:** هل أستخدم محاولة المعاينة الواحدة المسموح بها بمجرد تأكيد انتهاء العطل، أم تفضّل أن تنقر أنت إعادة المحاولة بنفسك وتخبرني بالنتيجة؟ (لا يمكن حسمه من المشروع لأنه يمسّ استهلاك الرصيد.)

لا توجد أي تعديلات مقترحة قبل نجاح المعاينة أو ظهور دليل مباشر أن المشكلة خاصة بالمشروع.
